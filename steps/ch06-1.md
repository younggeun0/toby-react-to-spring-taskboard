# ch06-1 · JPA와 H2를 붙이고 메모리를 DB로 갈아 끼우기

> 책 [6장 2절](https://library.younggeun0.dev/react-to-spring/06#s2)~[5절](https://library.younggeun0.dev/react-to-spring/06#s5)

`Task`에 `@Entity`를 붙이고, `TaskRepository`를 인터페이스 한 줄로 만들고, `TaskService` 안쪽의 메모리 `Map`을 리포지토리로 바꿨다.
**컨트롤러는 한 줄도 바뀌지 않았다.** 4·5장에서 계층을 나눠 둔 덕분이다.

```bash
git diff ch05-8 ch06-1 -- . ':!steps'
```

```
[변경 전]  컨트롤러 → 서비스 → 메모리(Map)
[변경 후]  컨트롤러 → 서비스 → TaskRepository → 데이터베이스
```

- `build.gradle`: `spring-boot-starter-data-jpa`, `com.h2database:h2`
- `application.properties` → `application.yml`: 원서가 yml로 설명해서 바꿨다. 메모리 H2, `create-drop`, `show-sql`

「앱 보충」 [6장 4절의 원문 보정 상자](https://library.younggeun0.dev/react-to-spring/06#s4)대로 했다.
원서의 `TaskService`는 엔티티를 주고받아서, 그대로 붙이면 5장 컨트롤러가 컴파일되지 않는다. 서비스의 공개 메서드는 5장 모양(DTO를 받고 DTO를 돌려준다)을 지키고, 안에서만 엔티티를 다룬다.
`TaskResponse`에 `description`이 있으니 엔티티에도 `description` 필드를 뒀다.

## 실행해 보기

```bash
./gradlew bootRun
```

시작 로그에서 Hibernate가 만든 테이블을 찾는다.

```
Hibernate: create table task (done boolean not null, id bigint generated by default as identity, description varchar(255), title varchar(255), primary key (id))
```

할 일을 만들고 목록을 본다.

```bash
curl -X POST http://localhost:8080/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": "JPA 붙이기", "description": "6장"}'
curl http://localhost:8080/api/tasks
```

콘솔에 SQL이 찍힌다. `save()`가 INSERT로, `findAll()`이 SELECT로 바뀌었다.

```
Hibernate: insert into task (description,done,title,id) values (?,?,?,default)
Hibernate: select t1_0.id,t1_0.description,t1_0.done,t1_0.title from task t1_0
```

이제 서버를 껐다 켜고 다시 목록을 본다.

```bash
curl http://localhost:8080/api/tasks
```

```
[]
```

DB를 붙였는데도 비어 있다. `jdbc:h2:mem:`은 메모리에 뜨는 DB라 프로세스와 함께 사라지고, `create-drop`은 시작할 때 테이블을 만들고 끝날 때 지운다. 지금은 "일단 동작"이 목표라 이 설정을 쓴다.

시작 로그에 `spring.jpa.open-in-view is enabled by default` 경고(WARN)도 보인다. 7장에서 이 경고의 뜻을 만난다.
