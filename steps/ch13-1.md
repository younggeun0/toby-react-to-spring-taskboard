# ch13-1 · 태그 붙이기 (예시 완주본 1)

> 책 [13장 3절](https://library.younggeun0.dev/react-to-spring/13#s3)~[5절](https://library.younggeun0.dev/react-to-spring/13#s5)

13장은 AI와 함께 기능 하나를 스펙 → 설계 → 구현 → 테스트로 완주하는 장이다. 정답이 하나가 아니다. 이 레포의 13장은 원서의 스펙을 따라 한 번 완주해 본 **예시**다. 먼저 내 AI 도구로 직접 해 보고(원서의 "Ask me questions", Plan Mode), 결과를 이 단계들과 비교하는 것을 권한다.

원서가 합의한 스펙:

> - 할 일(Task) 하나에 태그를 0개 이상 붙일 수 있다. (다대다)
> - 태그는 자유 입력 문자열. 같은 이름의 태그는 재사용한다.
> - 검색 조건: 제목 부분 일치(선택), 태그 이름 정확히 일치(선택). 둘 다 비면 전체 조회.
> - 결과는 페이징한다(한 페이지 20개).
> - 응답은 기존 `TaskResponse`에 태그 목록을 더한 모양.

이 단계는 앞의 두 줄과 마지막 줄, 곧 태그를 붙이고 응답에 싣는 데까지다. 검색은 다음 단계다.

```bash
git diff ch12-2 ch13-1 -- . ':!steps'
```

- `Tag` 엔티티: 이름은 `unique`. `TagRepository.findByName`
- `Task.tags`: `@ManyToMany` + `@JoinTable(name = "task_tags")`. 중간 테이블이 할 일과 태그를 잇는다
- `TaskCreateRequest.tags`: 선택 입력. 10개까지, 이름마다 비지 않고 30자 이하(`List<@NotBlank @Size String>`, 5장의 검증을 원소에도)
- `TaskResponse.tags`: 태그 이름 목록(이름순)
- `TaskService.create`: 같은 이름의 태그가 있으면 재사용하고 없으면 만든다
- `DataInitializer`: 초기 할 일에 태그(`공부`, `긴급`, `운동`)를 붙였다
- 5장 `TaskControllerTest`: `TaskResponse` 모양이 바뀌어 한 줄 고쳤다

## 검증 ②: SQL 로그로 N+1 보기

`GET /api/tasks` 직후의 SQL을 본다. 할 일 1번, 태그 1번이다.

```
select … from task t1_0
select t1_0.task_id, t1_1.id, t1_1.name from task_tags t1_0 join tag t1_1 on t1_1.id=t1_0.tag_id where t1_0.task_id in (?, ?, …)
```

8장의 `default_batch_fetch_size`가 이미 걸려 있어서다. `application.yml`에서 그 줄을 지우고 다시 보면 원서 5절의 그림이 나온다.

```
select … from task t1_0
select … from task_tags t1_0 join tag t1_1 on t1_1.id=t1_0.tag_id where t1_0.task_id=?
select … from task_tags t1_0 join tag t1_1 on t1_1.id=t1_0.tag_id where t1_0.task_id=?
… (할 일 수만큼)
```

다대다라 중간 테이블을 JOIN하는 모양이다([13장 5절의 원문 보정 상자](https://library.younggeun0.dev/react-to-spring/13#s5)). 확인했으면 `git checkout -- .`으로 되돌린다.

## 검증 ④: 트랜잭션 경계

`TaskService.findAll`·`findById`에 `@Transactional(readOnly = true)`를 붙였다. `TaskResponse.from`이 태그(지연 로딩)를 읽기 때문이다.
`findAll`의 그 줄을 지우고 `GET /api/tasks`를 보내 보자. 7장에서 OSIV를 꺼 두었으니 500이다.

```
LazyInitializationException: failed to lazily initialize a collection of role: com.example.taskboard.Task.tags: could not initialize proxy - no Session
```

8장 보정 상자가 말한 컬렉션 쪽 메시지가 바로 이것이다. 필요한 데이터는 트랜잭션 안에서 DTO로 바꿔 내보낸다. 확인했으면 `git checkout -- .`으로 되돌린다.
