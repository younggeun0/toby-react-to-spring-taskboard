**1. 인증 진입점** ([10장 6절의 원문 보정 상자](https://library.younggeun0.dev/react-to-spring/10#s6))

```java
.exceptionHandling(e -> e
    .authenticationEntryPoint(new HttpStatusEntryPoint(HttpStatus.UNAUTHORIZED)))
```

9장 설정에는 `httpBasic`이 있어서 Basic 인증의 진입점이 401을 썼다. 10장 설정에는 `httpBasic`도 `formLogin`도 없어서, Spring Security가 기본 진입점(`Http403ForbiddenEntryPoint`)을 쓴다. 그래서 ch10-3·ch10-4에서 토큰 없는 요청이 403이었다.

프런트 입장에서 둘은 다르다.
- **401 Unauthorized**: 누군지 모르겠다 → 다시 로그인시킨다
- **403 Forbidden**: 누군지는 아는데 권한이 없다 → "권한 없음"을 보여 준다

**2. 잘못된 토큰** (ch10-3의 남은 문제)

`JwtAuthenticationFilter`가 토큰 검증 예외(`JwtException`)를 잡는다. 잡으면 인증을 등록하지 않은 채 다음 필터로 넘긴다. 보호된 경로라면 위의 진입점이 401로 답하고, 열린 경로라면 익명 사용자로 그냥 처리된다.

## 실행해 보기

```bash
./gradlew bootRun
TOKEN=$(curl -s -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username": "ara", "password": "pass1234"}' | sed 's/.*"token":"\([^"]*\)".*/\1/')

curl -i http://localhost:8080/api/tasks                                        # 401 (토큰 없음)
curl -i -H "Authorization: Bearer garbage.token.here" http://localhost:8080/api/tasks  # 401 (형식 오류)
curl -i -H "Authorization: Bearer $TOKEN" http://localhost:8080/api/tasks       # 200
```

서명만 바꾼 위조 토큰도 401이다. 토큰의 마지막 조각(서명)의 글자를 몇 개 바꿔 보내 보자. 페이로드는 그대로 읽히지만 서명이 맞지 않는다.

ch10-3에서 500이던 엉터리 토큰이 이제 401이다. 서버 로그에 스택 트레이스도 남지 않는다.
