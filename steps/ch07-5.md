# ch07-5 · OSIV를 끄면 터지는 `LazyInitializationException`

> 책 [7장 5절](https://library.younggeun0.dev/react-to-spring/07#s5)~[6절](https://library.younggeun0.dev/react-to-spring/07#s6) · 「앱 보충」

`application.yml`에 한 줄을 더했다. 코드는 바꾸지 않았다.

```yaml
spring:
  jpa:
    open-in-view: false
```

```bash
git diff ch07-4 ch07-5 -- . ':!steps'
```

원서는 "트랜잭션 밖에서 지연 로딩을 건드리면 `LazyInitializationException`"이라고 설명한다. 하지만 Spring Boot 기본값(OSIV 켜짐)에서는 ch07-4처럼 예외 없이 로딩된다. 원서의 설명을 직접 보려면 OSIV를 꺼야 한다.

## 실행해 보기

```bash
./gradlew bootRun
```

시작 로그에서 `spring.jpa.open-in-view is enabled by default` 경고가 사라졌다.

```bash
curl -i http://localhost:8080/api/tasks/3/owner
```

```
HTTP/1.1 500

{"timestamp":"…","status":500,"error":"Internal Server Error","path":"/api/tasks/3/owner"}
```

서버 로그:

```
org.hibernate.LazyInitializationException: Could not initialize proxy [com.example.taskboard.User#2] - no session
```

`findTaskEntity`가 끝나면서 출석부가 닫혔다. 컨트롤러가 받은 `task`는 출석부에서 떨어진 준영속(detached) 객체이고, 그 안의 `user`는 아직 채워지지 않은 프록시다. 프록시를 채우려 해도 물어볼 출석부(세션)가 없다.

**이 단계는 `/owner`가 500을 돌려주는 것이 정상이다.** 다음 단계에서 고친다.

OSIV를 켜 두면 이 예외는 사라지지만, 요청이 끝날 때까지 DB 커넥션을 붙잡고 있고 컨트롤러·뷰 어디서든 쿼리가 나갈 수 있다. 이 레포는 이후 단계에서도 OSIV를 끈 채로 간다. 필요한 데이터는 트랜잭션 안에서 다 꺼내 DTO로 바꿔 내보낸다.
