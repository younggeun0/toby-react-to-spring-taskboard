# ch13-3 · 동작을 테스트로 못 박기 (예시 완주본 3)

> 책 [13장 6절](https://library.younggeun0.dev/react-to-spring/13#s6)

원서 넷째 박자의 두 테스트를 옮겼다.

```bash
git diff ch13-2 ch13-3 -- . ':!steps'
```

- `TaskSearchRepositoryTest`(`@DataJpaTest`): 원서의 `태그로_할일을_검색한다`. 「앱 보충」 원서가 "스펙대로 구성"이라고 비워 둔 준비 코드를 채웠다. "긴급"이 달린 할 일, "공부"만 달린 할 일, 태그 없는 할 일을 섞어 저장한다. 제목과 태그 조건을 함께 거는 테스트도 하나 더했다
- `TaskSearchControllerTest`(`@WebMvcTest`): 원서의 `검색어로_조회하면_200과_결과를_돌려준다`. 「앱 보충」 [13장 6절의 원문 보정 상자](https://library.younggeun0.dev/react-to-spring/13#s6)대로 고쳤다
  - `@WithMockUser`: 9장부터 보안 필터체인도 함께 뜬다
  - 가짜 `TaskService`는 `@MockBean`이 아니라 `@MockitoBean`
  - 가짜 `JwtTokenProvider`: 10장의 필터가 요구한다(ch10-3)
  - 가짜 서비스가 돌려줄 페이지를 `given(...)`으로 정했다. 정하지 않으면 가짜는 `null`을 돌려준다

## 실행해 보기

```bash
./gradlew test
```

```
BUILD SUCCESSFUL
```

`build/reports/tests/test/index.html`을 열면 지금까지 쌓인 테스트가 모두 보인다. 5장의 MockMvc, 7·8장의 `@DataJpaTest`, 9·10장의 단위 테스트, 13장의 검색 테스트. 손으로 `curl`을 치던 확인들이 이제 명령 하나로 다시 돈다.

## 직접 깨뜨려 보기: `@WithMockUser`를 빼면

`TaskSearchControllerTest`의 `@WithMockUser` 줄을 지우고 다시 돌린다.

```
Status expected:<200> but was:<401>
```

원서 그대로 붙였다면 여기서 빨간불을 봤을 것이다. 컨트롤러가 아니라 보안 필터가 막았다. 확인했으면 `git checkout -- .`으로 되돌린다.
