「앱 보충」 원서 코드에 없는 두 빈을 더했다.
- `UserDetailsService`: 폼 로그인이 DB의 사용자(`ara`/`pass1234` 등)로 로그인하게 한다. 없으면 Spring Boot가 만든 임시 사용자만 있고, 9장에서 본 대로 BCrypt 인코더와 맞지 않아 로그인이 안 된다
- `PasswordEncoder`: 지운 `SecurityConfig`에 있던 빈을 옮겼다

[11장 3절의 원문 보정 상자](https://library.younggeun0.dev/react-to-spring/11#s3)대로, 로그인 창구는 `/api/auth/login`이 아니라 폼 로그인이 만드는 **`POST /login`**이다. `/api/auth/login`(토큰 발급)은 남아 있지만 이 설정에서는 쓰지 않는다.

## 실행해 보기: 브라우저

```bash
./gradlew bootRun
```

1. 브라우저로 `http://localhost:8080/api/tasks`를 연다. 기본 로그인 폼(`/login`)으로 이동한다.
2. `ara` / `pass1234`로 로그인하면 처음 열려던 `/api/tasks`로 돌아와 JSON이 보인다.
3. 개발자 도구 Application(저장소) 탭 → Cookies → `http://localhost:8080`에서 `JSESSIONID`를 찾는다. **HttpOnly**에 체크돼 있다. 자바스크립트(`document.cookie`)로 읽을 수 없는 쿠키다.
4. 서버를 껐다 켜고 같은 탭에서 `/api/tasks`를 새로 고친다. 다시 로그인 폼이 나온다. 세션은 서버 메모리에 있었고, 쿠키는 그 세션을 가리키는 번호표일 뿐이었다. 서버가 재시작되면 번호표가 가리킬 곳이 사라진다.

## 실행해 보기: curl

로그인 폼에는 CSRF 토큰이 숨어 있다. 쿠키를 파일(`jar`)에 담아 가며 흉내 낸다.

```bash
curl -i http://localhost:8080/api/tasks
# 302, Location: http://localhost:8080/login

CSRF=$(curl -s -c jar -b jar http://localhost:8080/login | sed -n 's/.*name="_csrf" type="hidden" value="\([^"]*\)".*/\1/p')
curl -i -c jar -b jar -X POST http://localhost:8080/login \
  -d "username=ara&password=pass1234&_csrf=$CSRF"
# 302, Set-Cookie: JSESSIONID=…; Path=/; HttpOnly

curl -i -b jar http://localhost:8080/api/tasks
# 200
```

JWT 때와 달리 요청에 토큰을 싣지 않는다. 쿠키(`-b jar`)만 보내면 서버가 세션에서 사용자를 찾는다.

- 틀린 비밀번호: `302`, `Location: http://localhost:8080/login?error`
- `_csrf` 없이 `POST /login`: `403`. CSRF 보호가 켜져 있어서 로그인 요청조차 토큰이 필요하다([11장 4절의 원문 보정 상자](https://library.younggeun0.dev/react-to-spring/11#s4))
