# ch09-1 · Spring Security를 넣기만 해도 전부 잠긴다

> 책 [9장 2절](https://library.younggeun0.dev/react-to-spring/09#s2)~[3절](https://library.younggeun0.dev/react-to-spring/09#s3)

`build.gradle`에 `spring-boot-starter-security`를 더했다. 설정 코드는 아직 없다.

```bash
git diff ch08-5 ch09-1 -- . ':!steps'
```

「앱 보충」 의존성 하나로 5장의 `TaskControllerTest`가 깨진다(`Status expected:<400> but was:<403>`). `@WebMvcTest`가 보안 필터체인도 함께 올리기 때문이다. 그래서 테스트도 고쳤다.
- `spring-security-test` 의존성
- 테스트 클래스에 `@WithMockUser`: 인증된 가짜 사용자로 요청한다
- POST에 `.with(csrf())`: CSRF 토큰을 실어 보낸다(아래 ch09-2에서 CSRF를 만난다)

[13장 6절의 원문 보정 상자](https://library.younggeun0.dev/react-to-spring/13#s6)가 짚는 문제를 여기서 먼저 만난 것이다.

`CorsConfig`의 주석도 고쳤다. 5장에서는 Security가 없어 `CorsConfigurationSource` 빈을 아무도 읽지 않았지만, 이제는 Spring Security가 이 빈을 찾아 필터체인 안에서 CORS를 처리한다(ch09-2의 TRACE 로그에 `CorsFilter (5/13)`로 보인다). 5장의 `CorsFilter` 빈도 남아 있어 CORS가 두 번 처리되지만, 같은 설정이라 결과는 같다. 정리는 11장에서 한다.

## 실행해 보기

```bash
./gradlew bootRun
```

시작 로그에 임시 비밀번호가 찍힌다. 띄울 때마다 바뀐다.

```
Using generated security password: 465feece-d912-4f7a-83cc-4bfec2b64080

This generated password is for development use only. Your security configuration must be updated before running your app
```

```bash
curl -i http://localhost:8080/api/tasks
```

```
HTTP/1.1 401
WWW-Authenticate: Basic realm="Realm"
```

컨트롤러는 그대로인데 401이다. 요청이 컨트롤러에 닿기 전에 필터체인에서 막혔다. `/api/users/summary`도, 다른 모든 경로도 401이다. 기본값은 "일단 전부 잠근다"다.

사용자 이름 `user`와 로그에 찍힌 비밀번호로 다시 요청한다.

```bash
curl -i -u user:<생성된 비밀번호> http://localhost:8080/api/tasks
```

```
HTTP/1.1 200

[{"id":1,"title":"JPA 익히기",…}]
```

브라우저로 `http://localhost:8080/api/tasks`를 열면 기본 로그인 폼(`/login`)으로 이동한다. 기본 설정은 폼 로그인과 Basic 인증을 둘 다 켠다.
