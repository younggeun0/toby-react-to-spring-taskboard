# ch05-8 · `@MockitoBean`으로 테스트 통과시키기

> 책 [5장 6절의 원문 보정 상자](https://library.younggeun0.dev/react-to-spring/05#s6) · 「앱 보충」

테스트 클래스에 가짜 `TaskService`를 빈으로 넣는 한 줄을 더했다.

```java
@MockitoBean
private TaskService taskService;
```

```bash
git diff ch05-7 ch05-8 -- . ':!steps'
```

AI나 옛 글은 `@MockBean`을 주곤 하는데, Spring Boot 3.4부터 deprecated다. 3.5에서는 `org.springframework.test.context.bean.override.mockito.MockitoBean`을 쓴다.

「앱 보충」 원서가 "같은 방식으로 단언할 수 있다"고만 하고 넘어간 성공 경로 테스트도 더했다.
가짜 서비스가 무엇을 돌려줄지 `given(...).willReturn(...)`으로 정하고, 201과 응답 바디를 단언한다. 가짜(mock)를 넣는 이유가 여기서 드러난다. 컨트롤러 한 겹만 서비스와 떼어 놓고 검사할 수 있다.

## 실행해 보기

```bash
./gradlew test
```

```
BUILD SUCCESSFUL
```

`build/reports/tests/test/index.html`에서 `TaskControllerTest`의 테스트 2개가 모두 통과한 것을 확인한다.

## 직접 깨뜨려 보기: 테스트가 정말 지켜 주나

`TaskController`의 `@Valid`를 지우고 `./gradlew test`를 다시 돌린다. 이번엔 손으로 `curl`을 치지 않아도, 빈 제목 테스트가 빨간불로 알려 준다.
확인했으면 `git checkout -- .`으로 되돌린다.
