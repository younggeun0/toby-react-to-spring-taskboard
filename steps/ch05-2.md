# ch05-2 · DTO와 `POST /api/tasks` (아직 검증 없음)

> 책 [5장 1절](https://library.younggeun0.dev/react-to-spring/05#s1), [3절](https://library.younggeun0.dev/react-to-spring/05#s3)

요청과 응답을 나르는 DTO를 따로 만들고, 할 일을 만드는 `POST /api/tasks`를 추가했다.

```bash
git diff ch05-1 ch05-2 -- . ':!steps'
```

- `dto/TaskCreateRequest`: 요청 바디. `title`, `description`만 받는다. **`id`가 없다.**
- `dto/TaskResponse`: 응답 바디. 서버가 정한 `id`와 `done`이 들어 있다.
- 컨트롤러는 `ResponseEntity`로 상태코드 **201 Created**를 직접 고른다.

「앱 보충」 원서에 없는 코드를 채웠다.
- `Task`: 원서는 "`Task` 클래스가 있다고 가정하고 읽자"고만 한다. 6장에서 JPA 엔티티가 되기 전까지 쓸 평범한 클래스를 두었다.
- `TaskService.create`: 원서에 구현이 없다. 메모리 `Map`에 저장하고 `AtomicLong`으로 id를 매긴다. 서버를 재시작하면 목록이 비는 것이 정상이다.
- `GET /api/tasks`: 원서의 5장 컨트롤러 코드에는 POST만 있다. 목록 조회는 남겨 두고 `TaskResponse` 목록을 돌려주게 바꿨다.

## 실행해 보기

```bash
./gradlew bootRun
```

**1. 서버가 정한 id.** 요청에 `"id": 999`를 끼워 보낸다.

```bash
curl -i -X POST http://localhost:8080/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"id": 999, "title": "Spring 공부", "description": "5장"}'
```

```
HTTP/1.1 201

{"id":1,"title":"Spring 공부","description":"5장","done":false}
```

`TaskCreateRequest`에 `id`가 없으니 `999`는 에러 없이 조용히 버려지고, 응답의 `id`는 서버가 정한 값이다. 이게 요청 DTO와 응답 DTO를 나누는 이유다.

**2. 아직 엉성한 곳.** 빈 제목을 보낸다.

```bash
curl -i -X POST http://localhost:8080/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title": ""}'
```

```
HTTP/1.1 201

{"id":2,"title":"","description":null,"done":false}
```

빈 제목짜리 할 일이 아무렇지 않게 만들어졌다. 다음 단계에서 막는다.
