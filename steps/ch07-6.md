# ch07-6 · 지연 로딩은 트랜잭션 안에서 끝낸다

> 책 [7장 5절](https://library.younggeun0.dev/react-to-spring/07#s5)~[6절](https://library.younggeun0.dev/react-to-spring/07#s6)

ch07-5에서 깨진 `/owner`를 고쳤다. OSIV는 끈 채로 둔다.

```bash
git diff ch07-5 ch07-6 -- . ':!steps'
```

- 엔티티를 컨트롤러에 넘기던 `findTaskEntity`를 없앴다.
- `TaskService.findOwnerName`: `@Transactional(readOnly = true)` 안에서 할 일을 찾고 주인 이름까지 꺼낸다. 출석부가 열려 있을 때 지연 로딩을 끝내고, 컨트롤러에는 `String`만 돌려준다.
- 컨트롤러는 서비스를 부르기만 한다.

원서 `printUserName`이 `@Transactional` 메서드 안에서 `task.getUser().getName()`을 부르던 바로 그 모양이다. 트랜잭션 경계 안이 지연 로딩이 안전한 곳이다.
조회만 하는 메서드라 `readOnly = true`를 줬다. 더티 체킹을 위한 비교를 건너뛸 수 있다는 힌트가 된다.

## 실행해 보기

```bash
./gradlew bootRun
curl -i http://localhost:8080/api/tasks/3/owner
```

```
HTTP/1.1 200

bogum
```

SQL은 ch07-4와 똑같이 두 번 나간다. 바뀐 건 두 번째 SELECT가 나가는 자리다. 이제 컨트롤러가 아니라 서비스의 트랜잭션 안에서 나간다.

```
Hibernate: select … from task t1_0 where t1_0.id=?
Hibernate: select u1_0.id,u1_0.name from users u1_0 where u1_0.id=?
```

없는 id는 6장에서 만든 404 응답을 받는다. `POST`로 만든 할 일은 주인이 없어서 빈 응답(200)이 온다.
